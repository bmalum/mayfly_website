Run Elixir on AWS Lambda

Mayfly is a lightweight, open-source Lambda custom runtime for Elixir.

Write a handler module, run mix release, attach the Erlang layer. No Docker, no boilerplate, no silent failures.

Built and used in production by Karrer, an Elixir-on-AWS shop in Germany. MIT licensed.

Everything Lambda offers, in idiomatic Elixir

🧩

A behaviour, not a string

use Mayfly.Handler, implement handle/3, keep cold-start work in init/1. Compile-time checked; the Lambda handler setting is just the module name.

📦

mix release is the build

Three release steps produce lambda.zip. Umbrellas, multiple releases and config/runtime.exs work as they always did.

🪶

Erlang layer, no Docker

Public Lambda layers ship the Erlang runtime. Your zip is a few MB of BEAM files and builds on macOS, Linux or Windows in seconds.

🛡️

Honest errors

Exceptions, exits, bad return values, unencodable results and misconfigured handlers all reach Lambda as proper errors with Elixir stack traces.

🌊

Response streaming

Return any Enumerable. Function URL preludes, chunked encoding, mid-stream error trailers and backpressure are handled for you.

🧵

Managed Instances

One poller process per concurrency slot. Invocations run in parallel on the BEAM, isolated by design, up to 32 GB of memory.

🔍

Observable

JSON logs with request and tenant ids for CloudWatch, :telemetry events, X-Ray trace propagation.

🧪

Local first, agent friendly

mix lambda.invoke runs the real runtime against an emulated Runtime API; mix lambda.doctor catches setup mistakes. An Agent Skill and llms.txt teach coding agents the library.

An Elixir Lambda function is a module

The event is a decoded map, the context carries request id, deadline and tenant, the result becomes JSON.

defmodule MyApp.Handler do
  use Mayfly.Handler

  @impl true
  def init(_opts) do
    # runs once per execution environment (cold start)
    {:ok, %{table: System.fetch_env!("TABLE_NAME")}}
  end

  @impl true
  def handle(event, %Mayfly.Context{} = ctx, state) do
    {:ok, %{
      message: "Hello, #{event["name"]}!",
      request_id: ctx.request_id,
      remaining_ms: Mayfly.Context.remaining_time_ms(ctx),
      table: state.table
    }}
  end
end

From zero to Lambda in four steps

Requires Elixir 1.18+ and OTP 27+. Pin your OTP to the layer's version, e.g. mise use erlang@27.3.4.18.

  1. 1

    Add the dependency and a release

    # mix.exs
def project do
  [
    app: :my_app,
    deps: [{:mayfly, "~> 1.0.0-rc"}],
    releases: [
      lambda: [
        steps: [&Mayfly.Release.prepare/1, :assemble,
                &Mayfly.Release.bootstrap/1, &Mayfly.Release.zip/1],
        mayfly: [handler: MyApp.Handler, layer: true]
      ]
    ]
  ]
end
  2. 2

    Write the handler and try it locally

    mix lambda.invoke MyApp.Handler '{"name":"world"}'
mix lambda.doctor        # release config, handler, OTP vs. layer

    mix lambda.invoke runs the real runtime against an in-process Runtime API emulator, so errors, context and streaming behave exactly as in Lambda. Add --http to simulate a Function URL request.

  3. 3

    Build

    MIX_ENV=prod mix release lambda
# * creating _build/prod/rel/lambda/bootstrap
# * creating _build/prod/rel/lambda/lambda.zip (1570 KiB)

    Prefer to bundle the Erlang runtime instead of using a layer? Drop layer: true and run mix lambda.build --docker --arch arm64 (docker or finch).

  4. 4

    Deploy

    aws lambda create-function --function-name hello \
  --runtime provided.al2023 --architectures arm64 \
  --handler MyApp.Handler \
  --layers arn:aws:lambda:REGION:ACCOUNT:layer:mayfly-erlang-27-arm64:1 \
  --zip-file fileb://_build/prod/rel/lambda/lambda.zip \
  --role arn:aws:iam::ACCOUNT:role/lambda-role

    The handler setting is the module name. SAM, CDK and Terraform snippets are in the deployment guide.

Erlang runtime layers for AWS Lambda

BEAM files are architecture independent; only the Erlang runtime is not. Mayfly ships it as a Lambda layer, rebuilt weekly for the latest patch of each supported OTP major, for x86_64 and arm64, in 16 regions.

Pinned

mayfly-erlang-27-3-4-18-arm64

One OTP patch release. Pin the full ARN in your infrastructure code.

Alias

mayfly-erlang-27-arm64

Newest version always tracks the latest 27.x patch.

Your own

layer/build.sh && layer/publish.sh

Publish to your account or AWS Organization in minutes.

The bootstrap verifies the layer's ERTS matches your build before starting the VM, so a version mismatch fails with a readable message. Current ARNs: ARNS.md on the layers release · layer guide

Built for how Lambda works today

Implements the current Runtime API: invocation ids are echoed, tenant ids land in the context, error types follow Lambda's Category.Reason convention so the console classifies them correctly.

On Lambda Managed Instances a single environment serves AWS_LAMBDA_MAX_CONCURRENCY invocations in parallel, each in its own process. Verified on real hardware: eight concurrent invocations, one VM, 0.13 s wall time.

Cold start is BEAM boot: about half a second from the layer with a stripped release, single-digit milliseconds warm, ~85 MB resident.

Misconfigured handler? The function fails to start and Lambda reports Runtime.NoSuchHandler. Nothing is ever reported as a success that was not one.

Frequently asked questions

Can you run Elixir on AWS Lambda?

Yes. AWS Lambda has no managed Elixir runtime, but its OS-only runtime (provided.al2023) runs any program that speaks the Lambda Runtime API. Mayfly implements that API in Elixir, so an ordinary Mix release runs as a Lambda function.

How fast does Elixir cold start on Lambda?

With Mayfly and the Erlang layer a stripped release cold-starts in roughly 500–600 ms on arm64; warm invocations take single-digit milliseconds and use about 85 MB of memory. Keep init/1 lean and the package small.

Do I need Docker to build an Elixir Lambda function?

No. With the Mayfly Erlang layer the deployment zip contains only architecture-independent BEAM files and is produced by mix release on any OS. Docker (or finch) is only needed if you bundle ERTS yourself or have native NIF dependencies.

Does Mayfly support Lambda response streaming?

Yes. Return any Enumerable in a Mayfly.Response with stream/1; Mayfly uses chunked transfer encoding, adds the Function URL HTTP prelude and reports mid-stream errors via trailers. See the streaming guide.

Does Mayfly work with Lambda Managed Instances?

Yes. Mayfly starts one poller process per AWS_LAMBDA_MAX_CONCURRENCY slot so a single execution environment handles that many invocations in parallel. Handler state from init/1 is shared read-only.

Which Elixir and OTP versions does Mayfly require?

Elixir 1.18 or newer and Erlang/OTP 27 or newer. With the layer, your build toolchain's OTP must match the layer's OTP version exactly; mix lambda.doctor --layer ARN checks this and the bootstrap enforces it at start.

Can I run a Phoenix app on Lambda with Mayfly?

Mayfly is a function runtime: it hands your handler the Lambda event (API Gateway / Function URL payloads included). Plain Phoenix routing and LiveView expect a long-running HTTP server; for those the Lambda Web Adapter with a container image is the better fit. Mayfly shines for event-driven functions, APIs built on the proxy event, streaming responses and background jobs.

I'm on Mayfly 0.x. What changes?

The handler is a module with use Mayfly.Handler instead of a Module.function string (the old form still works), the build is mix release, and Elixir 1.18+ is required. The migration guide lists every change.
